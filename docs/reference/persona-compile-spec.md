# Persona Compile — Phase 2 spec (HELD: gated on Phase 1 A/B results)

**Status:** SPEC ONLY. Not implemented. Do not build until the Phase 1 gate passes.

**Phase 1 gate (the A/B):** run 2–3 real design tasks twice — `dcc` (persona core appended) vs plain
`claude` — and compare on NAMED behavioral deltas, not vibes: (a) did it state ENTRY/PATH/PACE before
building? (b) did rhythm/density actually vary down the surface? (c) did any basic-tell (eyebrow-mono,
bubble/box default, oversized type, uniform grid) ship without a stated context reason? If the deltas
are absent, the placement/register thesis fails — do NOT build this; invest in lane-slimming and
capability tier instead.

## What Phase 2 does (two moves, one change)

**Move 1 — bake the persona into the design agents at deploy time.** An agent's `.md` body IS its
system prompt. A compile step in the deploy path rewrites a marked block in the four design agents
(`agents/design/design-builder.md`, `design-validator.md`, `agents/ios-design/ios-design-builder.md`,
`ios-design-validator.md`):

```
<!-- PERSONA:BEGIN autogenerated from docs/concepts/design-contract/persona-core.md — edit the source, never this block -->
...persona-core.md content + the ~5-line role addendum...
<!-- PERSONA:END -->
```

- One shared core; per-role addendum only (builder: "record ENTRY/PATH/PACE in NOTES"; validator:
  "use the basic-tells as advisory vocabulary in FINDINGS — name the tell, never invent a block").
- Compiler fails the deploy LOUDLY if a marker pair is missing or unbalanced.
- The compiled block joins `deploy-diff.sh` drift checking; deployed-side hand-edits are drift, not law.
- Reload note: edited agent definitions take effect after a Claude Code session reload — acceptable
  for content that changes rarely.

**Move 2 — the injection diet (same change, never separately).** Once the stable register is baked
into agent bodies, the orchestrator STOPS injecting the full hub (~17–21KB) into builder and validator
per spawn and per retry. Runtime injection shrinks to per-task variables only: `TASK`,
`BOUND_CONSTRAINTS`, `USER_SHAPE`, `PRIOR_FINDINGS`, `ACTIVE_OVERRIDES`. The hub remains the
main-thread register (loaded once by the command), and the canonical files remain the single homes.
Doing Move 1 without Move 2 creates double-presence (same register at two weights) — dilution, the
exact failure this spec exists to remove.

**Rides along with this change:** revert the runtime persona-read steps added to the four agents on
2026-07-11 (builder step-1 persona reads + step 2b; validator step-4 persona sentences) — the compile
path strictly dominates that transport. `persona.md` (canonical source) and the hub §2 pointer lines
stay: they are documentation and bind the main-thread verbs.

## Compiler sketch

`scripts/compile-persona.sh` (run by the deploy script before sync):

1. Read `docs/concepts/design-contract/persona-core.md` (hard budget check: warn >55 lines, fail >70).
2. For each of the four agent files: locate `PERSONA:BEGIN/END`, replace the block body with core +
   that agent's role addendum (addenda live in the script or a small `persona-addenda/` pair of files).
3. Fail loudly on: missing file, missing/unbalanced markers, empty core.
4. Idempotent: running twice produces identical output (block content fully derived).

## Phase 3 (separate decision, not this spec)

Lane demotion: with standing taste in the main-thread system prompt, the bind→builder→validator lane
becomes the ESCALATION tier (net-new surfaces, big refactors), not the default path. Requires the
deterministic detector as a mandatory Stop-hook floor on main-thread design output — otherwise
main-thread self-grading re-enters the self-charity failure (`#POISON_PATH`) the validator exists to
kill. Decide after living with Phases 1–2.
