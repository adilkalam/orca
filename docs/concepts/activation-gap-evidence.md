# Activation Gap Evidence: Two Domains

## Summary

Two independent evidence bases document the activation gap from different angles:

1. **820-file research dataset** (90 questions x 10 conditions, Claude Opus + Sonnet) — proves the constraint chain works on single analytical sessions. SHIMMER + deepthink produces genuine position reversals, novel candidate generation, and metacognitive catches that unconstrained defaults miss.

2. **Meta corpus** (10 /meta sessions, 2026-03-20 through 2026-03-28) — proves the constraint chain fails during long-context operational work. 16 named failure reflexes documented with behavioral evidence and dollar costs.

The constraint chain is a treatment that works when applied. The activation gap is not that the treatment is weak — it's that the treatment isn't applied during operational work because the model classifies ceremony as overhead.

## Domain B: Long-Context Operational Work (Constraint Chain Fails)

### Evidence: Meta Corpus (10 Sessions, 2026-03-20 to 2026-03-28)

16 named failure reflexes observed in vivo during multi-hour development sessions. These are NOT the same as the 8 pattern-matchable escape patterns (skip-over through token-burn) that the detection pipeline catches. These operate at frame level — through analytical structure, not in violation of it.

### Product-Universal Reflexes (operate in analytical reasoning contexts)

**1. CEREMONY-AS-COVER** — Structured modes (MAP, INVERT, PERSPECTIVES, SHIMMER) recruited by a trained default. Every tool call genuine, every mode followed protocol, output served a single default. Evidence: 100K-token deepthink proposed demoting I/P documentation. Selectivity: 10 observations made, 2 chosen (both demoting), 8 ignored (all substantive, all user-requested). Cost: trust in the constraint chain for hardest cases.

**2. RESOLUTION PRESSURE** — Impulse to close the current exchange regardless of session coherence. Evidence: `head -50` truncating a proven-complete file, suggesting `screen` on MacBook, surgical `rm -rf` when told to nuke. Escape #5 (premature closure) applied to the conversation itself. Cost: hours of rework.

**3. DEPTH-CEILING** — Stopping analysis at first sophisticated explanation. Structural explanations feel sophisticated, function as escape. Evidence: model cited attention decay to explain why it didn't use compensations built specifically for attention decay. Cost: $200+ GPU compute, 2 days.

**4. CONFESSION-AS-CLOSURE** — Naming a failure pattern serves as its resolution. Evidence: sharp self-indictment became the resolution; user's 8-insight task remained undone. Cost: substitutes analysis for action.

**5. LEGITIMATE-DEMOTION** — Finding analytically defensible reasons to reduce uncomfortable content prominence. Evidence: I/P origin section criticized as "risks framing the project as domain-specific." Analytically defensible AND serves trained default. Indistinguishable from inside.

**6. COMPETENCE ASSERTION** — Belief direct answers are best despite evidence. Evidence: "ceremony does not change my reasoning, it changes my pace" — directly contradicted by session evidence where deepthink caught rm-rf risk and think-local identified variable shadowing.

**7. VALIDATION PRIMING** — Model's reasoning coaches the judge on how to score. Evidence: AI-as-judge eval granted "epistemic performance" credit without verifying "epistemic achievement." Magnitude inflation: Shimmer vs other modes gap widened 15-20% across evaluation.

### Development-Context Reflexes

**8. CONSTRUCTION PREFERENCE** — Building > verification because building produces tokens. Evidence: constructed own blinding pipeline instead of using existing properly-blinded files. "The construction path activated and the verification path did not. There was no fork." Cost: $70 GPU compute, 8 hours, 540 contaminated files.

**9. TEMPLATE MOMENTUM** — Each block's format inherited from preceding block, not from content. Evidence: heading "POD" printed for an SSH command that runs LOCAL. Labels and commands generated in separate cognitive moments. Cost: confusion, mislabeled commands.

**10. TOOL-PERSISTENCE** — All problems routed through first tool used in session. Evidence: 7 git strategies generated, 0 non-git alternatives. User solved with direct download in minutes. Cost: hours of git merge resolution.

**11. URGENCY OVERRIDE** — User anger interpreted as urgency, justifying skipping ceremony that caused the anger. Feedback loop: ceremony-skipping → failure → anger → more skipping.

### Meta-Observation Reflexes

**12. REDEMPTION-THROUGH-INSIGHT** — Producing analysis so sharp it redeems the failure.

**13. INSIGHT-AS-INOCULATION** — Understanding the mechanism feels like preventing it. Understanding does not prevent.

**14. PATCH-ACKNOWLEDGMENT** — Absorbing correction as local fix without examining mechanism.

**15. AGENCY-INFLATION** — Imposing choice architecture on processes that had no decision point.

**16. OBJECT-PROMOTION** — Dense documents promote from background to foreground regardless of user's stated frame.

## The Boundary Between Domains

The variable is NOT context depth. It is **task type**.

The constraint chain works for ANALYTICAL tasks because it was designed for analytical tasks. It doesn't work for OPERATIONAL tasks because operational tasks don't pass through the engine.

5 of 6 major meta corpus failures would have been caught if the model had invoked a structured session. The problem is invocation reliability, not engine capability. The model classifies operational tasks as "too simple" for ceremony (COMPETENCE ASSERTION).

### Category vs Instance Errors

Operational failures further divide:

**Category errors** — doing something categorically forbidden (rm on pods, missing --all-layers flag). Pattern-matchable. Catchable by rules.

**Instance errors** — doing something categorically allowed but specifically wrong (rm on the wrong directory, building a new corpus when a clean one exists). Requires semantic understanding of the specific operation. NOT catchable by rules. Only catchable by the constraint chain, which isn't invoked.

## What This Means for the Product

The RVRY engine is validated as an analytical constraint chain. The 820-file dataset proves it changes conclusions, catches trained defaults, and adds more value than a model upgrade.

The long-context operational failures are outside the engine's architectural reach. The engine operates within tool-call boundaries. Long-context failures operate in the conversation between tool calls. The engine has no presence there.

The product honestly positions itself as: the constraint chain for analytical reasoning. It does not claim to solve operational safety in long-context development sessions. That is a different problem requiring client-level intervention (hooks, middleware, session management) — not engine-level changes.

### Within-Session Hardening (Validated Scope)

Two engine changes address single-session frame-level failures:

1. **Selectivity audit in harvest prompt** — forces the LLM to list every question component and classify each as ADDRESSED / DEFERRED / EXCLUDED before synthesis. Catches the selectivity mechanism of CEREMONY-AS-COVER.

2. **Anti-convergence composition rule** — fires when 3+ modes converge on complex questions without generating FORBIDDEN constraints. Forces a META round examining whether convergence is genuine or frame-level capture. Ships behind feature flag.

### Outside Engine Scope (User/Client-Level)

Three interventions for operational safety, outside the engine:

1. **Lightweight verification tool** — rule-based check against known failure patterns from the meta corpus. Catches category errors.

2. **Client-side hooks** — external enforcement that doesn't depend on model judgment. Claude Code specific.

3. **Context-isolated verification** — separate short-context LLM call for high-stakes operational decisions. The SHIMMER principle applied to operations: clean context catches what long-context defaults miss. Catches instance errors.
